# Familles d'actions sensibles declarees dans `FamilleActionSensible` dont
# aucune action n'existe encore dans le depot. LS-81, ADR-027 decision 3.
#
# CE FICHIER EST UNE DETTE, PAS UNE EXEMPTION. Chaque ligne dit « cette famille
# n'est protegee par rien aujourd'hui parce que rien n'existe a proteger ».
# Le jour ou la premiere action d'une famille s'ecrit, sa ligne part d'ici : le
# controle echoue alors si l'action n'appelle pas la garde.
#
# Le controle refuse aussi une ligne perimee, c'est-a-dire une famille listee
# ici alors qu'une action la couvre : sans ce second sens, ce fichier
# deviendrait une decharge qui exempte a vie.
#
# Forme : NOM_DE_FAMILLE  puis la raison et le ticket qui la retirera.

DONNEES_CLIENTS     aucun acces au fichier client, voir la nuance ci-dessous, LS-36
REMBOURSEMENT       Stripe n'est pas branche avant la phase 4, phase 4
PARAMETRES_BOUTIQUE aucun ecran de parametres, hors phase 1

# LA LIGNE PARAMETRES_BOUTIQUE A ETE RELUE LE 13 AOUT 2026, LS-99, et elle reste
# vraie. La story ajoute deux ecrans d'administration, les categories du
# catalogue et la creation de produit, avec cinq Server Actions.
#
# AUCUNE N'EST CLASSEE, et la question a ete posee explicitement plutot que
# laissee implicite. La famille vise « les parametres de la boutique, dont les
# coordonnees bancaires » : une configuration d'exploitation, avec un effet
# financier ou contractuel. Une categorie de catalogue est du contenu editorial,
# reversible, sans effet sur l'argent ni sur les commandes passees.
#
# CE QUI RENDRAIT LA LIGNE FAUSSE, et qu'il faudra relire le moment venu :
# LS-98, parametres commerciaux, porte le seuil de franco de port et les frais
# de livraison. Ceux-la sont bien des parametres de boutique au sens de la
# famille, et la ligne devra partir a ce moment.
#
# LE RAISONNEMENT INVERSE A ETE ECARTE. Classer les categories aurait donne
# l'apparence d'une protection supplementaire sans rien proteger de plus :
# l'appelant doit deja etre ADMINISTRATRICE, compte unique, et une categorie
# renommee a tort se renomme a nouveau. Etirer une famille pour se rassurer est
# le meme defaut que l'etirer pour fermer une dette, en sens oppose.

# LES TROIS LIGNES ONT ETE RELUES LE 15 AOUT 2026, LS-102, et elles restent
# vraies. La story ajoute quatre Server Actions de medias : televersement,
# texte alternatif, reordonnancement, suppression.
#
# AUCUNE N'EST CLASSEE, et la question a ete posee plutot que laissee implicite.
#
#   DONNEES_CLIENTS     une photographie de bijou est du contenu de catalogue.
#                       Elle porte bien une donnee personnelle, la position GPS
#                       du domicile de L'EXPLOITANTE, mais la parade retenue est
#                       le TRAITEMENT qui la retire, ADR-007, et non une garde de
#                       fraicheur d'identite. Aucune donnee de client n'y figure.
#   PARAMETRES_BOUTIQUE meme raisonnement qu'en LS-99 pour les categories : du
#                       contenu editorial, sans effet sur l'argent ni sur les
#                       commandes passees.
#
# LA SUPPRESSION D'UN MEDIA EST POURTANT IRREVERSIBLE, l'original ayant ete
# detruit apres traitement : la photographie doit etre reprise au telephone.
# CE N'EST PAS UN CRITERE DE CLASSEMENT. Aucune des quatre familles n'est
# definie par l'irreversibilite, et etirer l'une d'elles pour couvrir ce cas
# serait le meme defaut qu'en LS-99, en sens oppose. Le geste est protege par
# une confirmation a l'ecran, qui vise l'erreur de manipulation.

# IDENTIFIANTS EST SORTIE DE CETTE LISTE LE 13 AOUT 2026, LS-95.
#
# `supprimerMonCompte` dans `src/app/compte/actions.ts` est la PREMIERE ACTION
# SENSIBLE REELLE du depot. Elle est rattachee a `IDENTIFIANTS` plutot qu'a une
# cinquieme famille : supprimer un compte emporte l'ensemble des moyens
# d'authentification, `Compte` et `Passkey` en CASCADE, ce que la definition de
# la famille decrit deja, « ce qu'un intrus fait en premier ». Le type est
# volontairement court, critere 6 de LS-81, et une famille pour une seule action
# se paierait en saisies quotidiennes sans rien proteger de plus.
#
# Le controle a REFUSE cette ligne des que l'action a existe, sens 3 : une
# famille declaree en attente alors qu'une action la couvre echoue. C'est ce
# sens qui empeche ce fichier de devenir une decharge qui exempte a vie.

# LA LIGNE DONNEES_CLIENTS A ETE CORRIGEE LE 13 AOUT 2026, elle etait FAUSSE.
#
# Elle disait « aucun export ni consultation en masse ». C'etait vrai quand
# LS-81 l'a ecrite, et cela a cesse d'etre vrai quand LS-80 a livre
# `src/app/administration/journal-connexions/page.tsx` : cet ecran affiche
# cinquante lignes portant adresse email, adresse IP et agent utilisateur de
# toute personne ayant tente de se connecter, CLIENTS COMPRIS. Le registre des
# traitements les recense en T8 comme donnees personnelles.
#
# Personne n'a relu ce fichier apres LS-80. C'est le motif deja rencontre trois
# fois sur ce projet : un etat ecrit au present dans un fichier que rien
# n'oblige a relire.
#
# POURQUOI CET ECRAN N'EST PAS CLASSE POUR AUTANT, arbitrage de Christophe du
# 13 aout 2026. Deux raisons, et aucune n'est un detail :
#
#   1. LA FINALITE DIFFERE. T8 est un traitement de securite, article 6.1.f,
#      distinct des traitements commerciaux T1 a T7. « Consulter les donnees
#      clients » au sens d'ADR-021 designe le fichier client : nom, adresse
#      postale, telephone, historique d'achat, factures. Le journal des
#      connexions n'en porte aucun.
#   2. « EN MASSE » Y SERAIT ETIRE. Cinquante lignes, sans recherche, sans
#      filtre, sans export : le volume est structurellement borne.
#
# Classer cet ecran aurait debloque sept criteres en dette de LS-81 et LS-89,
# et C'EST PRECISEMENT CE QUI DEVAIT RENDRE MEFIANT : elargir la definition
# d'une famille pour fermer une dette revient a deplacer la regle plutot qu'a
# la satisfaire. Le prochain lecteur d'ADR-027 ne comprendrait pas pourquoi un
# journal de securite est range en « donnees clients ».
#
# LE RISQUE RESTE OUVERT ET IL EST NOMME : sur un ordinateur laisse ouvert,
# c'est aujourd'hui le SEUL effet atteignable, et il donne a lire les traces
# qui documenteraient l'intrusion elle-meme. Il est borne par le fait que
# l'appelant doit deja etre ADMINISTRATRICE, compte unique.
#
# ---------------------------------------------------------------------------
# CE QUE `verifier-actions-sensibles.sh` NE PEUT PAS VOIR, et qu'aucun controle
# ne remplacera.
#
# Il confronte les marques `@sensible` au code dans les deux sens : une action
# marquee sans garde echoue, une famille listee ici alors qu'une action la
# couvre echoue aussi. Il prouve donc la COHERENCE entre marques et gardes.
#
# Il ne peut PAS dire qu'une marque manque. Un ecran sensible que personne n'a
# marque est invisible dans les deux sens : le controle reste vert, et cette
# liste continue d'affirmer qu'il n'existe rien a proteger. C'est exactement ce
# qui s'est produit ici entre LS-80 et le 13 aout 2026.
#
# LA PARADE EST HUMAINE : relire ce fichier a chaque story qui ajoute un ecran
# d'administration ou une Server Action, et se demander si la ligne est encore
# vraie. Aucun script ne pose cette question a la place de quelqu'un.
